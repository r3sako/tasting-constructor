# Конструктор дегустаций

Прототип для платформы «Своё Вино» (стипендиальный конкурс РСХБ 2026–2027, кейс «Своё Вино», задача 2).

Организатор собирает программу открытой или слепой дегустации из каталога российских вин, приглашает гостей
по QR-коду, гости оценивают вина со смартфона, а валидные оценки уходят в Народный винный рейтинг.

## Запуск

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python scripts/seed_demo.py
DEMO=1 .venv/bin/uvicorn app.main:app --port 8000
```

Откройте http://localhost:8000 и нажмите «Посмотреть демо-кабинет»: в нём четыре дегустации на разных этапах
(черновик, идёт голосование, закрыта и ждёт раскрытия бутылок, опубликована). Пароль для демо не нужен.

Чтобы гости могли войти с телефонов в той же сети Wi-Fi, запустите сервер на всех интерфейсах и укажите адрес,
который попадёт в QR-код:

```bash
PUBLIC_URL=http://192.168.1.10:8000 DEMO=1 .venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000
```

То же самое в Docker:

```bash
docker build -t tasting-constructor .
docker run -p 8000:8000 tasting-constructor
```

| Переменная | Назначение |
|---|---|
| `DEMO=1` | показывает кнопку входа в демо-кабинет |
| `PUBLIC_URL` | адрес для QR-кодов и ссылок на итоги, если он отличается от адреса запроса |
| `SECRET_KEY` | ключ подписи сессий и выгрузок; без него создаётся файл `data/.secret_key` |
| `RATING_API_URL` | адрес приёмника рейтинга; без него оценки принимает встроенная заглушка |
| `APP_DB`, `CATALOG_DB` | пути к базе приложения и к каталогу |

## Что сделано по условию задачи

| Требование | Где смотреть |
|---|---|
| Создание события | «Новая дегустация»: название, дата, место, открытый или слепой формат, способ входа, число мест |
| Подбор вин | Вкладка «Вина и программа»: поиск по каталогу с фильтрами по цвету, сахару, региону и сорту, кнопка «6 лучших по Народному рейтингу» |
| Программа | Порядок образцов, сеты, комментарии ведущего, случайное перемешивание для слепой дегустации |
| Вход по QR-коду | Вкладка «Приглашение» и экран для проектора; общий QR или одноразовые личные приглашения с печатью карточек |
| Настраиваемые шкалы | Вкладка «Шкалы»: три шаблона и свои критерии с диапазоном и весом |
| Заметки | Поле заметки в анкете гостя; в итогах заметки показаны без имён |
| Раскрытие бутылок | После закрытия слепой дегустации образцы раскрываются по одному, от последнего места к первому; гость видит название на телефоне сразу |
| Защита от повторных голосов | См. раздел ниже |
| Публикация итогов | Страница итогов по ссылке `/r/<код>`, доступна только после публикации |
| Передача в Народный рейтинг | Вкладка «Итоги»: кнопка передачи, просмотр выгрузки, журнал передач |

Экраны: кабинет организатора (`/org`), анкета участника (`/j/<код>` → `/t/<код>`), сводка результатов
(вкладка «Итоги» и публичная страница), экран для проектора (`/org/events/<id>/screen`).

## Защита от повторных голосов

1. **Одна оценка на вино.** В базе стоит ограничение уникальности «участник + вино»; повторная отправка обновляет
   оценку, а не добавляет вторую.
2. **Возврат в свою анкету.** Участник привязан к cookie с токеном; в базе хранится только хеш токена. Повторное
   сканирование QR возвращает гостя в его анкету.
3. **Повторный вход с того же устройства.** Если cookie сброшены (режим инкогнито), совпадение хеша устройства
   и адреса помечает нового участника как повтор. Его оценки не идут в итог, пока организатор не подтвердит,
   что это другой человек: два одинаковых телефона в одной сети Wi-Fi дают такое же совпадение.
4. **Одноразовые приглашения.** Строгий режим: у каждого гостя свой код, который срабатывает один раз.
5. **Лимит мест** и **окно голосования**: оценки принимаются только пока голосование открыто.
6. **Идемпотентная передача.** У каждой оценки постоянный идентификатор, поэтому повторная отправка в рейтинг
   дублей не создаёт.

## Какие оценки считаются валидными

В итоги и в рейтинг идёт оценка, если участник подтвердил, что ему есть 18, не исключён организатором, не помечен
как повторный вход и заполнил все критерии. Автоматически отсеиваются участники, поставившие всем винам одинаковые
крайние оценки (от четырёх вин). Правила лежат в `app/scoring.py`.

Оценка гостя приводится к шкале 1–5 Народного рейтинга: каждый критерий переводится в долю своего диапазона,
доли усредняются с учётом весов, результат равен `1 + 4 × доля`.

## Формат передачи в Народный рейтинг

Публичного API у рейтинга нет, поэтому в прототипе описан контракт и собрана заглушка приёмника
(`POST /mock/narodny-rating/v1/votes`). Запрос — JSON, в заголовке `X-Signature: sha256=<HMAC-SHA256 тела>`.

```json
{
  "schema": "svoe-vino.tasting-votes/1",
  "source": {
    "system": "tasting-constructor",
    "event_id": "sxbr5xttvn",
    "title": "Красные вина Крыма вслепую",
    "organizer": "Винный клуб «Терруар»",
    "tasting_mode": "blind",
    "access": "link",
    "held_at": "2026-10-07T19:00",
    "closed_at": "2026-10-07T17:00:00+00:00"
  },
  "scale": {
    "target": {"min": 1, "max": 5},
    "method": "weighted mean of min-max normalized criteria",
    "criteria": [{"name": "Аромат", "min": 1, "max": 10, "weight": 1.0}]
  },
  "votes": [
    {
      "vote_id": "0a7ba3c4b6dfc5c0da48703730afa26c",
      "wine_slug": "grenash",
      "wine_url": "https://vino-svoe.ru/wines/grenash",
      "score": 3.11,
      "voter": "a5cc1683dc5fa42b",
      "rated_at": "2026-10-07T16:49:00+00:00"
    }
  ],
  "summary": {
    "participants": 12,
    "valid_votes": 60,
    "excluded_votes": {"excluded_by_organizer": 6, "duplicate_device": 6, "uniform_extreme": 0, "incomplete": 0}
  }
}
```

- `wine_slug` — ключ карточки вина на vino-svoe.ru, платформе не нужно сопоставлять названия.
- `vote_id` вычисляется из события, участника и вина; приёмник по нему отбрасывает повторы.
- `voter` — обезличенный идентификатор; имена гостей в выгрузку не попадают.
- Ответ: `{"accepted": 60, "duplicates": 0, "rejected": []}`. Заглушка отклоняет оценки с неверной подписью,
  неизвестным вином и баллом вне диапазона 1–5.

Передача доступна после закрытия голосования, когда оценки уже не меняются. После первой передачи состав
валидных участников фиксируется.

## Данные

Каталог — `data/catalog.sqlite`: 2175 вин и их свойства с публичных страниц vino-svoe.ru (собрано 13.10.2026).
Приложение подключает его только на чтение и ссылается на вина по ключу карточки, поэтому в программу нельзя
добавить вино, которого нет в каталоге. Обновить каталог:

```bash
python3 scripts/fetch_catalog.py
python3 scripts/build_catalog.py
```

Оценки гостей в демо-кабинете сгенерированы скриптом `scripts/seed_demo.py` и к реальным людям не относятся.

## Тесты

```bash
.venv/bin/python -m pytest tests -q
```

25 сквозных сценариев: путь от создания события до публикации, расчёт шкал, каждое правило защиты от повторных
голосов, скрытие вин в слепой дегустации до раскрытия, состав выгрузки и повторная передача без дублей.

## Ограничения прототипа

- Приёмник рейтинга — заглушка: реальная интеграция потребует адреса и ключа от платформы.
- Нет ограничения частоты запросов и подтверждения почты организатора.
- Отпечаток устройства грубый и даёт ложные совпадения на одинаковых телефонах; для открытых мероприятий
  рассчитан режим одноразовых приглашений.
- SQLite и один процесс: достаточно для дегустации на десятки гостей, не для нагрузки платформы.
- Изображения бутылок загружаются с серверов vino-svoe.ru.

## Устройство

```
app/
  main.py      приложение, проверка источника POST-запросов, страницы ошибок
  db.py        схема базы и подключение каталога
  org.py       кабинет организатора
  guest.py     вход по QR и анкета участника
  public.py    главная, вход, страница итогов, заглушка приёмника рейтинга
  scoring.py   шкалы, приведение к 1–5, правила валидности, сводка
  export.py    формат выгрузки, подпись, передача
  security.py  пароли, токены, коды
  templates/, static/
scripts/       сбор каталога и наполнение демо-кабинета
tests/         сквозные сценарии
```

Стек: Python (проверено на 3.14), FastAPI, SQLite, шаблоны Jinja2, без сборки фронтенда.
